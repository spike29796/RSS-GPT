# REQ-摘要回填：最近未摘要条目逐步补齐

## 背景
第三阶段前端上线后发现：只有每天每源最新 max_items 条才有摘要，此前
未摘要的条目（超额度、摘要失败、清洗兜底）永远是空卡片。openai-news 的
1000+ 历史档案不应回填（逐条烧 API 额度且无意义）。

## 需求（用户决策：回填最近条目）
1. 每轮运行除新条目外，额外用独立预算为**最近 N 天内**未摘要的条目补摘要，
   最新优先，直到窗口内全覆盖。
2. 源级配置：`backfill_days`（时间窗口，默认 0=关）、`backfill_items`
   （每轮回填预算，默认 0=关）。qbitai 7天/5条、ithome 3天/10条；
   openai-news 与 awwwards-sotd 不开。
3. 回填只改条目的 summary/category/content，不改变条目集合与顺序
   （幂等语义：链接序列逐轮一致，已有摘要的条目不被改写）。
4. 回填输出不合规（解析兜底 None）时跳过，留给下一轮。

## 验收标准（DoD）
- `test/e2e_verify.py` 全绿：链接序列两轮一致、已摘要条目零改写、
  无 backfill 的源 XML 逐字节一致、backfill 源每轮实际新增摘要 >0
- 线上几天后 qbitai/ithome 最近条目卡片普遍有摘要

## 边界
- 不引入新依赖；不改 max_items 语义（新条目摘要预算与回填预算独立）
- 历史档案（超窗）永不回填
