# REQ-分类功能：RSS 摘要增加文章分类

## 背景
RSS-GPT 第一阶段已部署（见 README.md）。第二阶段准备做前端聚合展示，需要每篇文章带结构化分类，作为后续筛选/分栏的数据基础。

## 需求
1. 修改摘要 prompt：模型输出第一行为分类（仅限：模型发布/行业动态/政策法规/开源项目/产品应用），第二行起为 200 字内中文摘要。
2. 解析模型输出，分类写入生成的 RSS XML 的 `<category>` 字段。
3. 模型输出的分类不在五类之内时，兜底为「行业动态」，保证 XML 中 category 取值永远合法。
4. 摘要渲染格式不变（保留 `<br><br>总结:` 结构），不影响现有功能。
5. 旧条目（从既有 XML 读回的 existing_entries）重新渲染时保留原 category。

## 验收标准（DoD）
- 本地用 mock LLM + 真实三源（量子位/OpenAI News/IT之家）跑通，无报错。
- 生成的 3 个 XML 中每个 `<item>` 都有 `<category>`，且取值在五类之内。
- 连续运行两次，第二轮旧条目的 category 不丢失。
- 摘要内容仍正常生成（不为空、含「总结:」）。
- 用户在自己 fork 的 Actions 重跑一次，无报错（依赖其 secrets 已配置）。

## 边界
- 不改 openai SDK 调用方式、不改 config.ini 结构、不加新依赖。
- 英文 prompt 分支同步修改（解析逻辑共用，不能只对中文生效）。
- 未调用 LLM 的条目（超出 max_items 或摘要失败）分类统一兜底为「行业动态」。
