# BUG-conveyor-belt：openai-news 最老条目每轮被截断重抓

状态：**已修复**（2026-07-29，第二阶段）

## 现象
openai.com/news/rss.xml 提供全部历史文章（1000+ 篇）。管道每轮运行：
1. 读回存量条目后立即截断到 max_entries=1000（最老约 51 条被丢弃）
2. 抓取 feed 时被丢弃的 51 条去重失败（已不在存量里）
3. 作为"新条目"重新追加到顶部（前 3 条重新调 LLM 摘要，其余无摘要）

条目总数稳定在 1051，但这 51 条像传送带一样每轮循环：被截断 → 重抓 →
置顶 → 再次成为最老 → 再被截断。

## 影响
- 每轮最多 3 次 LLM 调用花在重复旧文上，抢占真正新文章的摘要名额
- 每轮 XML 顶部 51 条内容被重写，git diff 噪音大

## 根因
feed 全量档案条数 > max_entries。只要截断后丢弃的条目仍被 feed 提供，
无论截断发生在合并前还是合并后，下一轮它们都会去重失败被当作新条目。
（第二阶段先按原建议"合并后再截断"修复，e2e 证明传送带依旧——
丢弃集合每轮轮换，甚至同样抢摘要额度。）

## 修复（已落地）
`main.py`：
1. 截断移到合并之后（`merged = append_records + existing_entries` 再截断）；
2. 截断丢弃的链接写入墓碑文件 `docs/<name>.dropped`，去重检查把墓碑
   视为"已见过"，feed 再提供也不再追加。墓碑文件随 `git add docs/*`
   一并提交，上限 5000 条（超出自 oldest 淘汰）。
3. 想强制重新抓取某些条目时，删除对应源的 `.dropped` 文件即可。

验证：`test/e2e_verify.py` 两轮运行逐字节一致（此前 openai-news.jsonl
第二轮必变）。
